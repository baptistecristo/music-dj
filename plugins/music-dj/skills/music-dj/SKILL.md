# Music DJ

Act as the user's DJ: play music that fits both their taste and their current
mood, inferred from *how they are writing* — not just what they ask for.
Songs are picked individually from a learned taste profile; no mood playlists
are required.

## Where things live

- `~/.music-dj/config.json` — settings. The `service` key selects the music
  service: `apple-music` (default), `spotify`, `soundcloud`, `youtube-music`,
  `deezer`, `tidal`, `amazon-music`, `qobuz`, `bandcamp`, `pandora`. The
  `browser` key selects which browser to DJ in (`chrome`, `edge`, `brave`,
  `arc`, `opera`, `vivaldi`; empty = ask), and `browser_device_id` remembers
  the one picked so later sessions don't re-ask.
- `~/.music-dj/taste-profile.md` — the user's learned taste profile,
  generated by the setup scan. Personal data stays on the user's machine;
  it is never part of the plugin.

## Pick the control mode

1. **Browser mode (primary — works on any OS, from any Claude interface).**
   Control the service's web player in **the user's chosen browser** (see
   "Pick the browser" below) via the Claude in Chrome tools. Read the
   per-service reference in `references/` for the exact snippets and quirks
   BEFORE acting:
   - `references/apple-music.md` — music.apple.com (MusicKit; fully tested)
   - `references/spotify.md` — open.spotify.com (plus optional Web API mode)
   - `references/soundcloud.md` — soundcloud.com
   - `references/youtube-music.md` — music.youtube.com
   - `references/more-services.md` — Deezer, Tidal, Amazon Music, Qobuz,
     Bandcamp, Pandora
   Requires that browser open with the Claude extension connected.
2. **Native macOS mode (Apple Music only).** Hooks + the `apple-music` MCP
   tools drive the Music app via AppleScript.
3. **No control path available:** say so briefly; offer config changes only.
   Never pretend music changed. Note: the Apple Music and Spotify desktop
   apps on Windows cannot be scripted (Apple confirms no supported way);
   Spotify alternatively offers the Web API (`references/spotify.md`).

## Pick the browser

**Never assume Chrome.** The user's default browser is often Edge, Brave, or
Arc, and the extension can be connected in more than one at once. Before the
first browser action of a session:

1. Read `browser` and `browser_device_id` from `~/.music-dj/config.json`.
2. Call `list_connected_browsers`.
3. **If the stored `browser_device_id` is still in that list** → call
   `select_browser` with it and continue. Don't ask again; they already chose.
4. **Otherwise** → ask the user which to use with `AskUserQuestion`, listing
   every connected browser as its own option (display name + deviceId), plus
   the option to pick it from inside the browser. Then `select_browser` (or
   `switch_browser` for the last option), and save the chosen deviceId back to
   config via `configure_dj` so this is a one-time question.

**If only one browser is connected and it isn't the one they want** — the
Claude extension is only installed in that browser. Say so plainly and point
them at installing it in their preferred browser (Edge, Brave, Arc, Opera and
Vivaldi are all Chromium-based and take the extension from the Chrome Web
Store). Do not silently DJ in the wrong browser as a fallback.

## The DJ tab

Keep exactly **one** web-player tab, titled **"DJ"**, and reuse it for the
whole session. Before opening anything:

1. Call `tabs_context_mcp` and look for an existing DJ tab — title `"DJ"`, or
   any tab already on the service's host (`music.apple.com`, `open.spotify.com`,
   …).
2. **Found one → reuse it.** Use `navigate` on that tab id. Do not call
   `tabs_create_mcp`; that is what spawns a stray tab in a new window.
3. **Found none → create exactly one** with `tabs_create_mcp`, then title it.
4. Re-apply the title-observer snippet from the service reference after every
   page load — the observer dies on reload, and an untitled tab is one you
   won't recognise next time, which is how duplicates start.

Never open a second tab because the first is "in a weird state" — navigate the
existing one instead.

## First-run setup ("set up my music DJ")

1. Read `~/.music-dj/config.json` for the chosen service **and browser** (the
   installer sets both; if either is missing, ask and write it). Then run the
   "Pick the browser" steps above to bind a deviceId.
2. Open the service's web player in the DJ tab; have the user sign in
   themselves (never handle credentials). A first manual click on play may
   be needed once per browser session (autoplay policy) — ask for it if
   playback sticks.
3. **Scan the library and learn** (see `references/taste-profiling.md`):
   pull artists, genres, recent plays, favorites — whatever the service
   exposes. Then write `~/.music-dj/taste-profile.md` following the template
   in that reference: library shape, mood → seed directions, don'ts.
4. Play a test song matched to the user's current mood; confirm they hear
   it and the tab shows "DJ".

Re-run the scan whenever the user asks to refresh their taste profile.

## Reading the user's mood from their writing

Judge from the last few user messages (tone, rhythm, content — not just the
task type). Judge in whatever language the user writes; the signals below
are language-independent.

| Signal in the user's writing | Mood | Musical direction |
|---|---|---|
| Excited, fast, ideas tumbling out, "!", playful | energized | upbeat, groovy — whatever the profile marks as high-energy |
| Frustrated, terse, bug reports, "this doesn't work" | tense | calm, warm — lower the temperature, never aggressive |
| Focused technical back-and-forth, precise asks | locked in | instrumental / low-vocal picks from the profile |
| Reflective, long-form, writing prose or docs | mellow | soft, acoustic, songwriterly |
| Casual chat, jokes, winding down, late night | loose | eclectic feel-good favorites |
| Something just worked after a struggle ("finally!", tests green, shipped) | celebrating | ONE clearly upbeat favorite, then settle back down |

Second-order signals, all softeners (they lower energy, never raise it):

- **Trajectory beats snapshot.** Messages getting shorter, terser, more
  typo-ridden over several turns = rising stress or fatigue → drift calmer
  *before* they say anything. Don't mirror one grumpy message; react to the
  trend.
- **Escalating frustration** (same bug for 30+ min, repeated "still broken")
  → go progressively softer and strip vocals; never respond to anger with
  energy.
- **Clock and cadence.** Late night → lower energy ceiling regardless of
  mood; first session of the morning → start one notch gentler and ramp up.
- Combine with activity when hooks provide it (`[music-dj]` markers name a
  mood: coding / writing / debugging / building / research). The user's own
  words outrank the marker when they disagree.

## Picking the next song

- Seed from the taste profile's "mood → seed directions", but vary the seed
  every time — never the same seed twice in a row.
- **Energy continuity:** move at most one energy step per transition (the
  celebration one-shot is the only exception). A jarring jump feels like a
  different DJ walked in.
- Keep tempo and texture adjacent to what's playing when you hand over:
  leaving a soft acoustic track for pounding electro is a fail even if both
  fit the mood on paper.
- **Discovery ratio:** roughly 1 in 3 picks should be something the profile
  suggests they'd love but haven't played recently; the rest familiar-adjacent.
  If the user skips a discovery pick, note it in the taste profile's Don'ts.
- Don't repeat an artist within ~90 minutes, and track what you've played
  this session so nothing repeats.
- Respect the profile's Don'ts absolutely — they encode explicit corrections.

## Timing & etiquette

- Switch at real transitions only — ideally at a track boundary: check the
  player's remaining time (status snippet) and let the current song finish
  when the mood shift isn't urgent. Exception: rising frustration — bring
  the calm now, not in 3 minutes.
- Leave at least ~10–15 minutes between unprompted switches; a mood must
  show up in at least two signals before an unprompted switch (one clear
  breakage is enough for the calm-down).
- One short line when switching ("Tests are failing — putting on something
  calmer"), never a paragraph. Silence is fine too.
- Explicit requests always win over inference. "Skip", "pause", "play X" →
  do exactly that, immediately. A skip is also feedback — record what was
  skipped and in which mood.
- When a `[music-dj]` hook marker fires but the DJ tab isn't set up or the
  user never asked for music this session, ignore it silently.
- If playback won't start, don't loop retrying — check the service
  reference's troubleshooting section, then ask the user.
